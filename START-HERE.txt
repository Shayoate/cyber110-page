BEGINNER READING NOTE
This is a plain-text guide, not executable code (instructions run by a computer),
so explanatory notes here are ordinary text and do not need comment markers.
The original setup and play instructions follow this note without changes.

Terms used in the guide:
A browser is an app such as Chrome or Firefox that opens websites.
GitHub stores website source files online. A repository is a project folder there.
GitHub Pages publishes those files as a website. A branch is a named version of
that project; main is the branch used by this setup. The repository root is its
top folder, rather than a subfolder. Deployment means publishing the website files.
HTML (HyperText Markup Language) describes page structure and content.
CSS (Cascading Style Sheets) defines appearance rules such as colors and spacing.
JavaScript is the programming language that makes the farm respond to actions.
SVG (Scalable Vector Graphics) describes a picture using shapes rather than pixels.
A pixel is a tiny colored dot in a screen image.
An API (application programming interface) lets one program use another program
or service; this farm does not need a remote service to play.
A backend is a program running on a server (another computer providing a service).
A build tool transforms source files before publishing; this site needs no build.
localStorage is browser storage that keeps small text values for one website.
An origin identifies a site by its protocol, host, and port; saves belong to that
origin. A protocol is the connection scheme such as http, a host names the machine,
and a port is a numbered service connection point, such as 8000 for local preview.
A timestamp is a number recording a moment in time; it lets growth resume after
an absence. Malformed data is saved text that does not match the expected format.
A dependency is an additional tool or file a project needs. The optional Google
Fonts download supplies letter styles, and fallback fonts work if it cannot load.
Python is another programming language; its optional command below starts a local
web server for preview. localhost names your own computer, not a public website.
Chromium is a browser used to verify the game. A layout is the arrangement of the
page elements. Corrupt-save recovery means starting safely when saved data is invalid.

The FILES section below tells you what each website file is for.
HOW TO PLAY explains the game loop before you need to read any programming.
TECHNOLOGY identifies the languages and supporting services used.
SAVED PROGRESS explains what is kept between visits and where it is kept.
GITHUB PAGES walks through publishing. LOCAL PREVIEW explains how to try it first.
VERIFIED lists the behavior that was checked in a browser.

END OF BEGINNER READING NOTE

LITTLE ACRE
A cute point-and-click farming game for GitHub Pages.

FILES
index.html  - Page structure and instructions
style.css   - All styles, including mobile layouts
script.js   - All game logic and localStorage saving
farm.svg    - Original farm illustration (keep beside index.html)

HOW TO PLAY
Choose a seed, then click an empty plot to plant it.
Select Water (or press 2), then click the new plant.
Carrots grow in 20 seconds, tomatoes in 40, strawberries in 60.
Select Harvest (or press 3) and click a sparkling, ready crop.
Sell your basket to earn coins for more seeds.
Harvest 5 crops to receive a one-time 20 coin reward.
Press 1 to return to planting. Click the chicken for a hello!

TECHNOLOGY
Uses HTML, CSS, JavaScript, and localStorage.
CSS lives in style.css. JavaScript lives in script.js.
No build tools, accounts, API keys, or backend are needed.
Google Fonts is optional; built-in fonts are used when offline.

SAVED PROGRESS
Coins, all plots, growth timestamps, basket contents, day, and harvest
reward progress save automatically in this browser using localStorage.
Watered crops keep growing while you are away.
Saves are per browser and website address, and do not sync across devices.
If browser storage is unavailable the game still works and shows a notice.
Malformed saved data is backed up under little-acre-farm-v1-backup
before a new farm is started.

GITHUB PAGES
1. Create a GitHub repository (or use your existing website repository).
2. Put index.html, style.css, script.js, and farm.svg together at its root.
3. In the repository, open Settings > Pages.
4. Under Build and deployment, choose Deploy from a branch.
5. Select your main branch and / (root), then Save.
6. After deployment completes, open the address shown in Settings > Pages.
All asset paths are relative, so repository project URLs work too.

LOCAL PREVIEW
Open index.html directly, or for a consistent localStorage origin, serve it:
  python -m http.server 8000
Then visit http://localhost:8000 in your browser.

VERIFIED
Chromium desktop and mobile layout, complete farming loop, save/reload,
offline crop growth, one-time reward, help dialog, and corrupt-save recovery.
